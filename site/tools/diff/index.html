Reading a structural diff

Each line is one difference, addressed by JSONPath: $ is the document root, .key steps into an object, [3] into an array. Four things can happen to a value:

KindMeaningExample
changedsame type, different value$.user.age: 36 → 37
addedkey or element only on the right$.user.email: + "ada@example.com"
removedkey or element only on the left$.legacy: − true
typethe value's type itself changed$.id: 42 (number) → "42" (string)

Type changes get their own kind because they're the ones that break parsers downstream — an API quietly turning a number into a string is exactly what you want to catch in a contract change.

Why "identical" can still look different

{"a":1,"b":2} and a pretty-printed {"b":2,"a":1} are the same document: RFC 8259 defines object members as unordered, and whitespace is insignificant. If a system treats those two as different — canonical JSON, request signing, content hashes — that's a constraint the system adds on top of JSON, and you need byte-level comparison (text mode) instead.

Frequently asked questions

How is a structural JSON diff different from a text diff?

A text diff compares lines, so reformatting or reordering keys drowns you in noise. A structural diff parses both documents first and compares values by path: {"a":1,"b":2} and a pretty-printed {"b":2,"a":1} are identical structurally. You get a short list like $.user.age: 36 → 37 instead of pages of churn.

How are arrays compared?

By index by default: element 3 on the left is compared with element 3 on the right, so inserting one element near the front reports every later index as changed. When the elements are objects with an identifying field, enter it in match array items by key (e.g. id): elements are then paired by that value, an insertion reports one added item, and paths read $.users[id=42].name. Arrays with missing or duplicate keys fall back to index alignment.

Does key order matter in JSON?

Not to the format: RFC 8259 defines objects as unordered, and this differ ignores order. But JavaScript engines preserve insertion order in practice, and some systems (signatures, canonical JSON, JCS) depend on a specific serialization — that's a property of those systems, not of JSON itself.

Is my data uploaded when I compare?

No — parsing and diffing run entirely in your browser. Only the optional Share button uploads the two documents (up to 256 KB combined), and those links expire after 30 days.
