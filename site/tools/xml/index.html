Well-formed vs. valid

        

          XML draws a line JSON never needed: a document is well-formed when the syntax is right
          (every tag closed, one root, attributes quoted, & escaped) and valid when
          it also obeys a schema (DTD, XSD, RELAX NG). Browsers check well-formedness — and unlike HTML, XML parsers
          are draconian by spec: one bare ampersand and the whole document is rejected.
        


        
The five predefined entities

        

          
EntityCharacterMust be escaped

          
            
&amp;&always in text and attributes

            
&lt;<always in text

            
&gt;>only in the sequence ]]>

            
&quot;"inside double-quoted attributes

            
&apos;'inside single-quoted attributes

          
        

        

          Everything else (&copy;, &nbsp;…) is an HTML habit — in XML those are
          undefined unless a DTD declares them. Use numeric references like &#169; instead.

CDATA: the escape hatch

        

          <![CDATA[ raw <text> & symbols ]]> tells the parser "don't interpret any of
          this" — handy for embedded code or markup samples. The only thing it can't contain is the terminator
          ]]> itself.
