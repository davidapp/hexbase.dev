Y2038: the 32-bit cliff

A signed 32-bit time_t tops out at 2³¹−1 seconds: 2038-01-19 03:14:07 UTC. One tick later it wraps to −2³¹ — 1901-12-13. Modern 64-bit systems are safe for 292 billion years, but embedded devices, old file formats and 32-bit fields in protocols keep the bug alive. If you see a date in December 1901 or January 1970, suspect an overflow or a zero.

ISO 8601, the one true string format

  date      time      offset   ·  Z means +00:00 (UTC)

Big-endian dates sort lexicographically — ls sorts them chronologically for free. RFC 3339 is the internet profile of ISO 8601: stricter, and what APIs should emit.

Leap seconds & smearing

UTC has gained 27 leap seconds since 1972 to track Earth's slowing rotation; Unix time pretends they don't exist (each leap second, one Unix second repeats). GPS time never adds them, which is why GPS is currently 18 s ahead of UTC. Google and AWS "smear" the extra second across the surrounding day instead. A new wrinkle: Earth sped up recently, and a negative leap second is on the table before the practice is abolished (currently planned around 2035).
